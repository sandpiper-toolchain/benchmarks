River Bedform Geometry Benchmark — Paraná River

Problem

Given a set of 1-D bathymetric bed-elevation profiles from the Paraná River, detect individual bedforms in each profile and extract their key geometric properties:

Property Symbol Unit
Bedform height H m
Bedform length L m
Bedform depth d m

Submissions are a single CSV file — one row per detected bedform, across all 370 profiles.

This benchmark is an adaptation of the exhaustive testing in a 2024 peer-reviewed study. The study should be referenced and cited for complete information and proper attribution.

Scheiber, L., Zomer, J., Wang, L., Cisneros, J., Gutierrez, R. R., & Lefebvre, A. (2024). Automated bedform identification—A meta-analysis of current methods and the heterogeneity of their outputs. JGR: Earth Surface. https://doi.org/10.1029/2023JF007607

Why intercomparison, not scoring

There is no authoritative ground-truth delineation for this dataset. Expert analysts differ substantially in which bedforms they identify and in the geometric measurements they assign to each. The goal of this benchmark is therefore not to rank methods against a reference, but to place any new tool or workflow in context alongside documented methods from the literature. Comparing the distributions of H, L, and d — and the total number of detected bedforms — reveals method-specific biases and sensitivities that would otherwise be invisible.

Input data

File Description
data/Parana-370BFPs_Format-NT2D/ParanaBFP-<N>.txt 370 bed-elevation profiles (NT2D format; see below).

Data provenance

The profiles were collected from the Paraná River. The original publication for the data is Parsons et al., 2005.

The data are distributed with the Bedforms-ATM software package:

Bedforms-ATM. Available at: https://sourceforge.net/projects/bedforms-atm/

NT2D file format

Each ParanaBFP-<N>.txt file contains a single profile in NT2D format:

<profile_index>
<point_index>  <x_nominal_m>  <x_precise_m>  <z_m>
<point_index>  <x_nominal_m>  <x_precise_m>  <z_m>
...
  • Line 1 — the integer profile number (matches <N> in the filename).
  • Lines 2 onward — tab-separated: sequential point index, nominal downstream distance (m), precise downstream distance (m), and bed elevation (m, negative downward).

Submission format

A single CSV file named results.csv with one row per detected bedform:

Column Type Required Description
profile_id int No Profile number (1–370; matches ParanaBFP-<N>.txt).
height_m float Yes Bedform height H (crest elevation minus trough elevation), in metres.
length_m float Yes Bedform length L (crest-to-crest or trough-to-trough distance), in metres.
depth_m float Yes Bedform depth d (depth of the bedform trough below the local mean bed level), in metres.

Rows may be in any order. Include a header row.

Example (with optional profile_id):

profile_id,height_m,length_m,depth_m
1,0.85,42.3,0.52
1,0.72,38.1,0.44
2,1.14,55.0,0.68
...

Example (without profile_id):

height_m,length_m,depth_m
0.85,42.3,0.52
0.72,38.1,0.44
1.14,55.0,0.68
...

Intercomparison summary

The scorer reads every results.csv in submissions/, computes distribution-level summary statistics for each geometry column, and writes results_table.json. Run it locally (from the repository root):

python score.py river_dunes --compile

The compiled table reports, for each submission:

Field Description
n_bedforms Total number of detected bedforms across all profiles.
height_m {mean, median, std, p25, p75} of H across all bedforms.
length_m {mean, median, std, p25, p75} of L across all bedforms.
depth_m {mean, median, std, p25, p75} of d across all bedforms.

How to submit

  1. Fork this repository.
  2. Create a folder under submissions/ named after your method, containing results.csv and metadata.yaml (copy the metadata template from an existing submission).
  3. Open a pull request. CI regenerates results_table.json and publishes it with the website on gh-pages; generated result files are not committed to main.
